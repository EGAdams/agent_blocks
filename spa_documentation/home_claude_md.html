CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Overview

A scratch/experiment repo of independent "agent blocks" — small standalone Python scripts plus a set of agent system prompts. Not a git repo. No package, build system, dependency manifest, or test suite; every script is run directly with python3 from within its own directory.

Three top-level areas, unrelated to each other except in theme:

  • catherine_agent_sdk/ — Claude Agent SDK probe script
  • lancedb_memory/ — two generations of the same idea: the original RAVEN-style script (3o_mini_chat_w_lance.py, OpenAI), and agent_memory/, its ported successor on the Claude Agent SDK with Protocol-based ports
  • solid_agent_systems/ — one directory per SOLID-principle review agent

Running

cd catherine_agent_sdk && python3 basic_agent.py
cd lancedb_memory    && python3 3o_mini_chat_w_lance.py   # legacy, OpenAI
cd lancedb_memory    && .venv/bin/python main.py          # current, Claude SDK

Dependencies are not declared anywhere; install ad hoc:

  • basic_agent.py → claude-agent-sdk (not installed in the default interpreter — importing it currently raises ModuleNotFoundError)
  • 3o_mini_chat_w_lance.py → openai (legacy pre-1.0 API surface: openai.Embedding.create, openai.ChatCompletion.create), lancedb, pyarrow, pandas

catherine_agent_sdk/basic_agent.py — Agent SDK probe

Single-turn query() against the Claude Agent SDK, then dumps the ResultMessage: status, error flag, session id, per-model usage/context-window stats, and cost. The point of the script is the result-inspection block — ResultMessage.is_error is where auth/model/execution failures surface, since they do not raise.

The comments at the top of the file matter: ANTHROPIC_API_KEY and ANTHROPIC_BASE_URL must be unset for the SDK to use the local Claude Code subscription auth rather than direct-API billing.

lancedb_memory/3o_mini_chat_w_lance.py — vector-recall chatbot

An infinite REPL loop:

  1. Embed user input (text-embedding-ada-002, 1536 dims).
  2. Persist the turn as a uuid-named JSON file in the nexus directory.
  3. Vector-search LanceDB for the convo_length (30) most similar past turns.
  4. load_conversation() re-reads those turns' JSON files from disk, sorts chronologically, and joins them into the recalled transcript.
  5. Fill the prompt_response.txt template (<<CONVERSATION>>, <<MESSAGE>>), call chat completion, log prompt+response to gpt3_logs/.
  6. Persist and index the assistant turn the same way, then tbl.add() both turns.

Key design point: LanceDB stores the vectors, but the JSON files on disk are the source of truth for message text. Both must be written for recall to work; an emptied or missing nexus directory silently degrades recall to an empty conversation (load_conversation prints file not found and skips).

External paths/files the script requires but which are not in this repo:

  • key_openai.txt (cwd) — OpenAI API key
  • prompt_response.txt (cwd) — prompt template
  • /home/adamsl/linuxBash/agents/nexus/ — per-turn JSON store
  • /home/adamsl/linuxBash/agents/run.txt — alternate input when USE_RUN_TEXT = True
  • /tmp/lancedb — LanceDB dir, table youtube-chatbot

These hardcoded absolute paths are load-bearing; changing one means changing both the write site (save_json calls) and the read site (load_conversation).

lancedb_memory/agent_memory/ — the current agent

The successor to 3o_mini_chat_w_lance.py. Read lancedb_memory/README.md first; it documents the layout, the patterns, and the design decisions. Has its own venv at lancedb_memory/.venv (pydantic, lancedb, pyarrow, claude-agent-sdk) because the system interpreter is PEP 668 externally-managed.

The rules that matter when touching it:

  • agent_memory/agent.py may import .models and .ports and nothing else. That single greppable rule is the DIP boundary. lancedb, pyarrow, and claude_agent_sdk appear only under agent_memory/adapters/, and main.py is the only module that names a concrete implementation.
  • LanceDB is the sole read path. The table stores the message body; recall never touches the filesystem. nexus/ is a write-only archive behind NexusArchiveObserver, kept so raw text outlives any particular vector store. This is the fix for the legacy script's dual-source-of-truth bug — deleting the nexus must not affect recall, and a test asserts it.
  • Embeddings are lexical, not semantic (HashingEmbedder, 256 dims), because Anthropic serves no embeddings endpoint. Swapping in a semantic embedder changes the vector width; LanceDBMemoryStore raises on a dimension mismatch rather than writing unsearchable rows, so a new table name is required.
  • Tests run with no network and no API key: .venv/bin/python tests/test_agent.py and tests/test_lancedb_store.py.
  • Paths all default inside the repo via config.py — do not reintroduce the legacy script's hardcoded /home/adamsl/linuxBash/... absolutes.

solid_agent_systems/ — SOLID review agents

Intended layout, one directory per principle:

<principle_agent>/
  <principle_agent>.md   # the agent's system prompt
  src/<principle_agent>.py  # the runner

Only dependency_inversion_master/ is filled in. Its .md is a complete, carefully-specified system prompt worth reading before touching anything here — it defines the house style these agents enforce:

  • typing.Protocol for dependency abstractions (not ABCs), concrete types injected from a composition root/factory
  • Pydantic BaseModel is mandatory for structured data crossing boundaries; no new dataclasses, NamedTuples, or ad-hoc dicts as substitutes
  • explicit type annotations on params, returns, and Protocol methods
  • smallest reasonable repair only, and a fixed output format (## DIP Result → VIOLATION / POSSIBLE VIOLATION / NO SIGNIFICANT VIOLATION, then ## Reason, ## Dependency, ## Corrected Code)
  • an explicit anti-over-engineering rule: do not abstract str, int, Path, datetime, simple value objects, etc.

Known state, so you don't mistake it for a design: the other four (single_responsibility_guru, open_closed_sme, queen_liskov, interface_segregation_king) are empty 0-byte .md stubs with no src/, and dependency_inversion_master/src/dependency_inversion_master.py is currently a byte-for-byte (modulo spacing) copy of catherine_agent_sdk/basic_agent.py — the prompt is not yet wired into it, and the copied script still asks "Are you able to access the web?".

Style

basic_agent.py and its copy use an unusual spacing convention inside call parens and f-string braces (print( f"Status: { final_result.subtype }" )). 3o_mini_chat_w_lance.py uses a lighter, inconsistent variant of the same habit (print( 'file not found:', filename)). Match the surrounding file rather than normalizing it.

agent_memory/ and everything under it (plus basic_agent.py and the dependency_inversion_master.py copy) additionally enforce the closing-bracket half of this rule strictly: every non-empty ), ], or } gets a space before it — str ), [ 0.0 ], { "a": 1 } — while an empty pair stays tight ((), [], {}). This applies to every bracket type, not just call parens. The space belongs only next to the innermost non-bracket content: when closing brackets are adjacent, they stack with no space between them — ] ) becomes ]), and ] ) ) becomes ])), however deep the nesting. When adding code to these files, write closing brackets this way from the start rather than relying on a cleanup pass afterward.
