1.1 The one idea to understand first

Before worrying about the Claude Agent SDK, Toyota's dashboard, or Pipecat, learn this sentence:

Key Idea A ClaudeAgentAdapter is one small class whose only job is to make the Claude Agent SDK answer to IConversationAgent.

That is all it is.

Toyota's voice pipeline never calls claude-agent-sdk directly. It calls submit(text, generation) on whatever implements IConversationAgent. The adapter's entire purpose is translation at that one boundary.

1.2 Think of it as a translator at a border crossing

Picture two countries: the voice pipeline's country, where every request is shaped like submit(text, generation), and the Claude Agent SDK's country, where every request is shaped like query(prompt=...) and every answer is a ResultMessage.

A translator stands at the crossing. Nothing on the voice-pipeline side needs to learn the SDK's vocabulary, and nothing on the SDK side needs to learn the voice pipeline's. The translator — the adapter — is the only thing that speaks both languages.

University Principle An adapter's job is translation at one boundary, not decision-making. Policy belongs above the port; wire-format details belong below it.

1.7 What a ClaudeAgentAdapter is not

It is worth being precise here, because the name invites a natural but wrong assumption.

Common Misreading "ClaudeAgentAdapter" does not mean "a way to message this specific conversation." It means "a way to make a fresh claude-agent-sdk session answer to IConversationAgent."

Each submit() call can open a new SDK session. That session has no memory of, and no channel back into, whatever Claude Code conversation happens to be reading this page. The adapter is reproducible — any other instance can construct one the same way — precisely because it does not depend on any single running session existing.

Compare this to the loose, ad-hoc alternative it replaces:

1.10 The 30-second version

Exam Answer ClaudeAgentAdapter will implement IConversationAgent by wrapping claude-agent-sdk's query() call, checking ResultMessage.is_error before mapping the result to AgentEvents. It is a sibling of LettaAgentAdapter, not a channel into any particular Claude Code conversation: every call can spin up a fresh SDK session, which is what makes the pattern reproducible for other instances rather than tied to one running session.

1.12 The mental model to carry forward

Picture the translator at the border crossing again.

She does not decide policy for either country. She does not remember any one traveler once they walk past her booth. She only ever does one thing:

  • take a request shaped like submit(text, generation);
  • speak it in the Claude Agent SDK's language;
  • check whether the SDK's answer means success or failure;
  • hand back a stream of AgentEvents shaped exactly like any other adapter would.

Any translator built the same way could stand at that same booth.

Final Principle A reproducible adapter is not one that remembers who built it. It is one where the recipe — port in, concrete SDK call out — is complete enough that any other instance could follow it and get the same booth.
