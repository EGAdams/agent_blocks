Stage 1 of 5 — Declare the test seams

What this step is for Turn every host and headed/headless difference into an object the rest of the suite can hold without inspecting.

1. What this stage actually means

A suite that runs on two hosts grows host checks everywhere unless somebody decides early where those differences are allowed to live. This stage makes that decision: one abstract factory for the host family, and Null Objects for everything that only happens when a human is watching.

It is finished, and that is a modest milestone: a declared seam proves the differences are expressible, not that the suite starts anywhere.

2. The work inside this stage

StepWork itemStatusWhat it must deliver
1Write the platform profileDoneOne abstract factory supplying the spawn plan, browser path, flags and window focuser.
2Give every headed-only behaviour a Null ObjectDoneStepGate, HoldOpenNotice and WindowFocuser, so a headless run has nothing to check.
3Hold the expected navigation as dataDoneOne module, no imports, listing exactly what app.js should render.

Steps 2 and 3 are authored inline in the plan file; open them through the SPA's task navigation.

3. How to check this stage yourself

grep -rn "isWindows" browser_tests/ returns two hits, in test-config.ts and composition-root.ts. A third hit means a host check has leaked into a consumer, which is exactly what this stage exists to prevent.
