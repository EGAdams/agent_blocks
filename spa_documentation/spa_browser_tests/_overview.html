What Browser Tests is

Every other section here documents a project that lives one level up, in the agent_blocks workspace. This one documents this repository — the characterization suite at spa_documentation/browser_tests/ that drives the documentation SPA you are reading right now.

It exists because app.js is 1,301 lines and is about to be replaced by the strict-TypeScript design under app/. Before any of that reaches index.html, something has to fail loudly when behavior changes. Six Playwright tests launch a real Chrome against a real server.py on an ephemeral port and pin down what the current navigation does — home nav, all five detail tabs, deep links with anchors, invalid-route fallback, embedded mode, and both canonical lessons with their Mermaid figures and terminal buttons.

Where it stands

npm test reports 6 passed, 0 failed in about eight seconds. npm run typecheck passes across app/, app_tests/ and browser_tests/.

Two things are open. The Chrome path is a hard-coded constant in both platform profiles with no environment override, so a fresh checkout fails at browser launch rather than running. And the Update Documentation lifecycle — the largest single behavior in app.js — is still unpinned: the tab is opened and its HTTP status checked, but nothing asserts what it then does.

The blocks

  • Characterization Suite — the whole suite, with a five-stage construction plan. Two items carry full lessons: the Platform Profile abstract factory that absorbs every Windows/WSL versus Linux difference, and the Characterization Suite tests themselves.

Two things worth knowing before editing here

  • The folder is spa_browser_tests/, not browser_tests/. The latter is already taken on disk by the source this documents. Its doc_source_map.py branch resolves against DOCS_ROOT rather than REPO_ROOT for the same reason.
  • Adding a top-level nav section is a four-place change. Two of the six tests assert the home navigation exactly and in order, so HOME_NAV_LABELS in browser_tests/nav-fixtures/nav-fixtures.ts has to be updated in the same commit. That red run is the mechanism that makes a nav change deliberate instead of accidental — adding this very section is the worked example, in the Characterization Suite lesson, figure 2.
