01

What this system is

Voice Communication is the path from a spoken sentence to a Letta agent doing something about it, and back to speech. The dashboard already has a working path: browser capture, transcription, narrow Letta-backed decisions, agent execution, and edge-tts output.

The difficult part is not proving that voice works. It is bringing the working path under one typed session model, then introducing Pipecat without letting a media framework own Toyota's application policy.

Running

Dashboard voice stack

The live system under dashboard/voice/, dashboard/router/, and dashboard/js/.

Built, unused

Typed browser core

VoiceSession, the conversation-agent port and adapters, and SpokenOutputPolicy already exist in letta-code, but renderers do not call them.

New target

Agent Blocks architecture

TypeScript policy, Pydantic wire models, and a separate local Pipecat service, built one visible block at a time.

Read this twice. The Agent Blocks files are new skeletons; several similarly named objects are already implemented and tested in letta-code. When a block becomes active, the first task is to decide whether to migrate, adapt, or replace that existing object—not to blindly build a duplicate.

The contract atlas

LIVE DASHBOARD — proven behavior
  Python strategies      transcription · cleanup · routing · receptionist intent · synthesis
  Browser ports          listener · recorder · note surface · transcript buffer · speaker
  Clear-input seam       TranscriptSyncedNote can reset both stores; Start Listening does not call it
  Direct renderer seam   InputOptionsRenderer → /api/letta-code-message

BUILT IN LETTA-CODE — tested, no live renderer caller
  VoiceSession           lifecycle + generation fence
  IConversationAgent     submit(turn, generation) → AgentEvent stream
  LettaAgentAdapter      current request/response endpoint adapter
  FakeConversationAgent  offline and contract testing
  SpokenOutputPolicy     one gate before speech

AGENT BLOCKS TARGET — skeleton
  TypeScript             Toyota/application ports and compile-time shapes
  InputDraft             synchronized visible-text + transcript-state mutation
  Pydantic               fail-closed JSON request/event validation
  PipecatServiceClient   typed adapter across the process boundary
  PipecatLocalService    Python facade in a separate local process
  PipelineFactory        Pipecat construction only; no application policy
  VoiceHealthObserver    health, latency, interruption, and fallback events

Dependency rule: policy imports no Pipecat, Letta transport, STT provider, TTS provider, browser API, or logging implementation. Concrete construction belongs at the outer composition boundaries.

04

Construction sequence

  1. 0
    Lock the wire contract.

    Keep TypeScript contracts and Pydantic models aligned; add a parity test when the first service endpoint is implemented.

  2. 1
    Adopt IConversationAgent and LettaAgentAdapter in Toyota.

    Replace InputOptionsRenderer's direct fetch without changing visible text behavior.

  3. 2
    Give Toyota a VoiceSession.

    Move turn ownership into the session and prove that late output is rejected.

  4. 3
    Gate speech and wire interruption.

    Use SpokenOutputPolicy, then make speech start interrupt the active generation.

  5. 4
    Add ConversationCoordinator.

    Keep it framework-neutral: transcripts in, policy and agent ports out.

  6. 5
    Build the separate Pipecat service.

    Implement PipecatServiceClient, PipecatLocalService, and PipelineFactory before individual provider details fan out.

  7. 6
    Compose ToyotaVoiceApplication.

    Connect Toyota's Input Options behind a reversible feature switch while the current path remains available.

  8. 7
    Observe and roll out.

    Measure health, end-of-speech latency, first audio, interruption, disconnects, and fallback.

06

Known hazards

Built does not mean adopted

The existing green tests prove the objects work in isolation. They do not protect Toyota until a live renderer owns them.

Cancellation is delivery-side

The current endpoint can suppress a late response but cannot stop the remote Letta run. Do not promise hard cancellation.

State must have one owner

When VoiceSession is adopted, delete the equivalent renderer closure state. Two owners create a false fence.

Renderer lifetime differs from listener lifetime

Input renderers are rebuilt on navigation; listeners may survive it. Session placement must account for replies that outlive a tab.

Pipecat owns media, not policy

Pipecat may own frames, VAD, STT/TTS plumbing, interruption propagation, and pipeline lifecycle—never routing or speakability decisions.

Fail closed at every boundary

Unknown JSON, agent ambiguity, stale generations, and unhealthy local service state must not produce guessed behavior.

What “ready for the next block” means

  • The active block has typed source, focused tests, a real class diagram, and a real sequence diagram.
  • Its Construction Status names live callers and evidence—not merely files that exist.
  • The dashboard's current behavior still works, or the feature switch restores it immediately.
  • Only then does the next stub become active work.
