Three decisions carry it. import type vanishes at compile time, so this file can never drag a vendor SDK behind it. generation tags the request on the way in, which is what lets a superseded answer be discarded when the user interrupts. AsyncIterable makes the reply a stream, because an answer arrives in pieces over seconds.

These pages call a file like this a plug-in point — an opening with a written-down shape, so different components can be plugged in later without the surrounding code noticing. Here it is literally a TypeScript interface; line 3 uses the textbook word for it, port.

    User->>Screen: asks "Summarize our adapter plan"

    Iface->>Adapter: the call lands on whatever was injected
    Adapter->>Backend: vendor request (SDK, HTTP, websocket)
    Backend-->>Adapter: vendor messages, in the vendor's own shape
    Adapter-->>Screen: assistant_text: "We agreed to use one interface"
    Adapter-->>Screen: assistant_text: "with swappable adapters."
    Note over Adapter,Screen: Translation happens here and nowhere else. Only the five agreed kinds cross this line.
    Adapter-->>Screen: terminal: generation 2 is complete
    Screen->>User: renders the reply, then closes the turn
  1. The user starts a new request by asking the screen to summarize the adapter plan.
  2. The screen starts a new turn and receives generation 2, a token identifying this as the current turn.
  3. The screen submits the request through IConversationAgent; it knows the interface, but not the concrete adapter behind it.
  4. The interface call is dispatched to whichever adapter was injected when the application was assembled.
  5. The adapter translates the common submit call into the selected backend's SDK, HTTP, or websocket request.
  6. The backend returns vendor-specific messages that the adapter must translate before the screen can use them.
  7. The first assistant_text event carries the beginning of one streamed sentence: “We agreed to use one interface”.
  8. The second assistant_text event completes that same sentence with “with swappable adapters.” The screen appends it to step 7.
  9. The terminal event tells the screen that generation 2 has no more response chunks.
  10. The screen displays the joined sentence as one reply and closes the completed turn.

Figure 2. Here generation is a current-turn token, not a model version: when turn 2 begins, late events from interrupted turn 1 can be ignored. Vendor message shapes stop at the adapter, and only AgentEvent values cross back to the screen.

  • Step 3 is the point of the whole file. The screen writes one line and never learns which adapter it holds; that is chosen at the composition root.
  • Steps 6–9 are the translation seam. A vendor message arrives at the adapter; two distinct normalized text chunks and a terminal event come out.

5. What has to happen next

  1. Settle AgentEvent — Stage 2, in progress. TypeScript requires sessionId, pydantic_models/models.py requires session_id: UUID, and the Python adapter's copy has no session field and only two of the five kinds. Until they agree, no adapter can emit a legal event without inventing data.
  2. Decide who owns the session id. Either submit() hands it down or the event stops carrying it. It cannot stay required by one side and unknown to the other.
  3. Answer the interrupt question. Cancelling a turn is not on this interface yet: either a second method every adapter must implement, or a separate lifecycle interface. Deferred deliberately, not forgotten.
  4. Write a TypeScript adapter — Stage 3. Python proves the shape is implementable; nothing yet proves it in the browser.
  5. Make one screen depend on it — Stage 4. Until a real consumer calls submit(), this is a well-supported hypothesis.
