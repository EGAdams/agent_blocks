What this step is for Text arrives before the terminal event, and nothing follows a terminal.

1. What this item actually means

Consumers rely on ordering whether or not it is written down. A voice policy that speaks on assistant_text and closes the turn on terminal is broken by an adapter that emits them out of order — it will cut itself off mid-sentence.

The Python adapter already behaves correctly here: it holds the ResultMessage aside and yields terminal only after the stream is exhausted. This test generalizes that from one implementation's habit into the plug-in point's rule.

2. How we will know it is done

A terminal or error event is always last, and no event of any kind follows it.

3. How to continue from here

This is a leaf: the smallest unit in this plan, small enough that one person can finish it and prove it in one sitting. Nothing under it is hidden.

Construction principle A status follows the work you can go and look at: a test that runs, a screen that works, a file that is really there. It never follows how finished the idea feels.
