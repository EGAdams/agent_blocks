Constructing the Input Draft

One authoritative reset for Toyota's visible text and transcript state

1. Why this block exists

Toyota's current textbox is not the whole draft. Continuous recognition also keeps a committed transcript in memory. Clearing only the HTML control leaves that hidden prefix alive, so the next spoken phrase can restore and extend old text.

Ownership Rule The Input Draft owns synchronized text mutation. It does not decide when listening starts, where a message is sent, or whether an asynchronous result is still current.

2. Evidence already present

The dashboard already has a NoteDocument boundary, an EditableDarkNoteSurface, a TranscriptBuffer, and a TranscriptSyncedNote decorator. The new block captures the smallest reusable contract those objects are already pointing toward.

3. Completion standard

A single clear() call must empty the visible value and the transcript's committed and interim state. Tests must prove that the next accepted speech fragment begins at an empty draft.
