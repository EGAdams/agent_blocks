Constructing the Voice Session

Making old microphone and agent callbacks harmless

1. Why a session is required

Clearing the draft fixes the present state. It cannot recall a callback already queued by an older listening attempt. VoiceSession supplies a generation fence so every asynchronous result can prove that it still belongs to the active capture or turn.

Current EvidenceA tested dashboard VoiceSession already models conversation states and agent-turn generations. The Agent Block must extend that idea deliberately to microphone-capture generations.

2. Completion standard

Restarting listening, stopping listening, interrupting, or closing must invalidate older generations before their results can mutate the draft or reach speech output.

State PatternThe session owns legal state and freshness. It does not mutate UI text or perform network requests.
