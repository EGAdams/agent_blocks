Constructing Toyota's Voice Application

Wiring Agent Blocks into Input Options without hiding policy in the renderer

1. The composition boundary

ToyotaVoiceApplication is the Facade assembled at dashboard boot. It receives the concrete browser or Pipecat capture adapter, synchronized input draft, voice session, conversation coordinator, Letta adapter, output policy, and health observer.

Migration RuleInputOptionsRenderer becomes a view and event source. The Facade wires its Send and Start Listening controls to the coordinator; the renderer no longer performs direct conversation HTTP.

2. Completion standard

The live Toyota Input Options page must clear old text at the start of a fresh listening capture, clear accepted Send text, reject late callbacks, preserve conversation resume, and work first with the existing browser listener and then with the Pipecat client behind the same ports.

Facade PatternComposition chooses concrete adapters. Application policy remains testable and independent of the dashboard DOM, Letta, and Pipecat.
