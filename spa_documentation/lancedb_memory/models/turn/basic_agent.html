1.1 The one idea to understand first

Before worrying about embeddings, vector databases, similarity search, or prompt composition, learn this sentence:

Key Idea A Turn is one thing that one speaker said at one moment in one conversation.

That is all it is.

If the user sends one message, that becomes one Turn. If the agent answers once, that answer becomes another Turn.

The conversation may eventually contain thousands of turns, but the storage system does not need thousands of different shapes. It needs one dependable shape repeated many times.

University Principle Make the smallest useful data contract boring, strict, and predictable. Complexity can be added around it later.

Notice what is not here:

  • no embedding vector;
  • no similarity score;
  • no database-specific record ID;
  • no prompt-formatting instructions;
  • no model provider;
  • no retrieval rank.

Those concerns belong elsewhere.

Design Boundary Turn describes the utterance. It does not describe every operation that may later be performed on the utterance.

1.4 The five fields

Each field answers one small question.

FieldQuestion it answersWhy it exists
id: UUIDWhich exact turn is this?Gives every utterance a stable unique identity.
session_id: strWhich conversation owns it?Keeps independent conversations from becoming mixed together.
speaker: SpeakerWho said it?Restricts the answer to the known roles USER or AGENT.
message: strWhat was said?Stores the actual utterance.
created_at: datetimeWhen was it said?Preserves conversation order and temporal context.

1.11 Common misconceptions

“A Turn is the whole conversation.”

No. A conversation or session contains many turns.

— □ ×

“A Turn is a pair of user message + agent answer.”

No. Those are two separate turns because they came from two different speakers at two different moments.

“A Turn should contain its vector.”

Not necessarily. The vector is a representation used by a particular memory mechanism. It is not part of the fundamental utterance.

“speaker could just be any string.”

It could, but that would weaken the contract. Restricting known roles catches mistakes and makes downstream code safer.

1.12 The 30-second version

Exam Answer A Turn is one validated conversation utterance. It has a unique ID, session ID, speaker, message, and timestamp. The agent creates one for each user message and one for each agent reply. The rest of agent_memory uses that small model as a shared contract. Embeddings and recall metadata live in specialized wrappers so the core model stays clean.

1.14 The mental model to carry forward

Picture a university librarian recording a conversation.

She does not store “the entire memory system” on each index card.

She records only the facts that belong to the utterance:

  • which conversation;
  • which speaker;
  • what was said;
  • when it happened;
  • and which exact record it is.

Later systems may photocopy the card, index it, embed it, rank it, recall it, or place it into a prompt.

But the card remains the card.

Final Principle The smaller and cleaner the shared core model, the easier it is to build sophisticated machinery around it without turning the whole system into spaghetti.
